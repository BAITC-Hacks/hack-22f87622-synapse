# EventMatch — рабочая спецификация

EventMatch решает кейс «Умный подбор подрядчиков (#79-lite)»: по городу, дате, формату, категории и бюджету возвращает не более трёх профилей из локального каталога и объясняет выбор только проверяемыми фактами. Язык и длительность необязательны.

## Инварианты

- Дата находится в окне 2026-09-23—2026-12-31 и сравнивается как календарная строка без преобразования часового пояса.
- Сначала выбираются город и категория, затем применяются дата, формат, бюджет, язык и длительность.
- Границы бюджета и длительности включительны; `max_hours=null` означает отсутствие ограничения.
- Рабочий порядок: цена по возрастанию, затем `id`; AI не меняет кандидатов и порядок.
- Доменные исходы: `matched`, `no_category_in_city`, `no_matches`.
- Для исключённого профиля сохраняются все причины, а первичная выбирается в порядке дата → формат → бюджет → язык → длительность.
- AI может выбирать только уже рассчитанные `evidenceId`, разрешённый акцент для выбранного факта и, при пустом результате, одну реально присутствующую диагностическую причину; всё проверяется по серверным evidence и счётчикам, а итоговый текст строит сервер. Без ключа и при любой ошибке используется детерминированный fallback.
- Приложение не бронирует, не принимает оплату, не ищет подрядчиков снаружи и не обещает окончательную цену.

## Источник

Первичный источник — переданный CSV. HTML-файл является вспомогательным превью и не используется как полный календарь. Исходная CSV-копия хранится неизменённой в `data/raw/`.
